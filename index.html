주요 화면

핵심 문제 해결

이 프로젝트의 핵심은 AI 분석 기능 자체보다, 장시간 외부 AI 요청이 포함된 처리를 어떻게 서버 구조 안에서 안정적으로 다룰 것인가였습니다.

문제
  • AI 요청을 동기 방식으로 처리하면서 응답 지연이 발생했습니다.
  • 외부 AI API 응답을 기다리는 동안 서버 스레드가 장시간 점유되었습니다.
  • 요청이 늘어날수록 다음 요청들이 대기열에 쌓이며 처리량이 급감했습니다.
해결
  • AI 요청 처리 흐름을 비동기 구조로 전환
  • 상태 엔티티를 QUEUED / RUNNING / DONE / FAILED 로 설계
  • 즉시 202 Accepted 반환 후 백그라운드 작업으로 분리
  • 외부 AI 호출 실패에 대비한 재시도 및 상태 추적 구조 보완
  • k6 기반 부하 테스트로 동기/비동기 처리 비교 검증
결과

병목 원인이 단순 AI 지연이 아니라 동기 처리로 인한 스레드 점유와 대기열 누적에 있음을 확인했고, 비동기 처리 구조 도입 후 서버 안정성과 처리 흐름을 개선할 수 있었습니다.

전체 영상 분석 흐름 시간 단축

비동기 처리 흐름

Client 요청을 API Server가 즉시 접수하고, Async Worker가 AI API 호출과 상태 업데이트를 분리 처리하는 구조로 설계했습니다.

내 역할

  • 외부 AI 서버와 연동되는 영상 분석 요청 API와 처리 흐름을 담당했습니다.
  • 동기/비동기 구조 비교 실험을 위한 Mock AI 서버 지연 환경과 k6 부하 테스트를 설계했습니다.
  • 상태 기반 처리 구조와 예외 처리 흐름을 설계해 분석 작업의 진행 상태를 추적 가능하게 만들었습니다.

고찰

  • 장시간 외부 AI 호출이 있는 기능은 요청 흐름과 상태 관리를 함께 설계해야 안정적으로 동작한다는 점을 배웠습니다.
  • 비동기 구조의 필요성을 감이 아니라 k6 부하 테스트로 검증한 경험이 가장 컸습니다.
  • 상태 기반 처리는 진행 상황 표시가 아니라 장시간 작업을 신뢰성 있게 추적하기 위한 핵심 설계였습니다.
